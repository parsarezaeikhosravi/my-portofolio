# Security Policy

## Supported Versions

Currently, only the latest release of Parsa Studio is supported with security updates and patches. Please ensure you are running the most up-to-date version from the `main` branch.

| Version | Supported          |
| ------- | ------------------ |
| 1.x.x   | :white_check_mark: |
| < 1.0.0 | :x:                |

---

## Reporting a Vulnerability

**Please do not report security vulnerabilities via public GitHub issues.**

If you discover a security vulnerability or bug within the Parsa Studio portfolio, CRM, or authentication modules, we appreciate your help in disclosing it to us responsibly. 

To report a vulnerability, please follow these steps:

1.  Email your findings directly to the lead developer at **`parsarezaeikhosravi@gmail.com`**.
2.  Include a detailed description of the vulnerability, including:
    *   The steps required to reproduce the exploit (Proof of Concept).
    *   The potential impact of the vulnerability.
    *   Any suggested mitigations or fixes if available.
3.  We will acknowledge your report within **48 hours** and provide a timeline for resolution.
4.  Please keep all information regarding the vulnerability confidential until a patch is released to protect other users and clients.

---

## Vulnerability Response Process

Once a vulnerability report is received, Parsa Studio follows a coordinated disclosure process:

1.  **Verification:** We will verify the vulnerability and assess its severity.
2.  **Remediation:** We will develop a security patch or mitigation.
3.  **Testing:** We will test the patch across multiple viewports and orientations to ensure no regressions occur.
4.  **Release:** A new patched version will be committed to the `main` branch, and the reporter will be credited (if desired) in the release notes.
5.  **Target Timeline:** We aim to release a patch for all verified critical vulnerabilities within **7 to 14 business days** of receiving the report.
